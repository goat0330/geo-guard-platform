# 复盘报告查询接口对接文档

## 1. 文档说明

本文档用于复盘报告页面前后端联调，当前包含两个已完成的查询接口：

| 页面区域 | 接口 | 用途 |
|---|---|---|
| 左侧事件列表、地图定位及地图弹窗 | `GET /dizai/taskHandle/list` | 分页、筛选并返回事件卡片数据 |
| 右侧事件详情 | `GET /dizai/taskHandle/reviewDetail/{id}` | 返回事件概况、影响情况、现场资料、处置时间线和数据缺口 |

接口前缀均为：

```text
/dizai/taskHandle
```

日期时间统一按以下格式返回：

```text
yyyy-MM-dd HH:mm:ss
```

### 1.1 前端特别注意

灾害处置主键可能是 18 位数字，例如 `260920000000000001`，已经超过 JavaScript
`Number.MAX_SAFE_INTEGER`。前端必须将 `id`、`handleId`、`reviewReportId`、报告 `id`
等 Long 类型主键按字符串保存和透传，不能执行 `Number(id)`、数学运算或隐式数值转换。

如果当前请求库在 JSON 解析阶段会把大整数直接转换为 JavaScript Number，需要配置大整数解析，
或者在原始响应转换阶段将这些主键保留为字符串。

### 1.2 空值约定

- 当前数据库确实没有的数据返回 `null`，不返回虚构值；
- 集合字段没有数据时返回空数组 `[]`；
- 数量字段没有数据时通常返回 `0`；
- 右侧详情的 `dataGaps` 会列出已识别的数据缺口；
- `0` 是有效人数或状态值，前端不能使用 `value || '-'` 判断空值，应只判断
  `value === null || value === undefined`。

## 2. 公共枚举

### 2.1 复盘状态

| 编码 | 名称 | 前端建议展示 |
|---:|---|---|
| `0` | 待复盘 | 可查看详情、补充资料、生成复盘 |
| `1` | 生成中 | 展示生成进度，暂不可重复发起 |
| `2` | 待确认 | 可查看或编辑草稿、重新生成、确认 |
| `3` | 已确认 | 展示正式复盘报告 |
| `4` | 已归档 | 当前 UI 暂无独立入口，保留兼容 |

前端应优先展示后端返回的 `reviewStatusName`，枚举主要用于按钮状态控制。

### 2.2 事件类型

| 编码 | 名称 |
|---:|---|
| `1` | 滑坡 |
| `2` | 崩塌 |
| `3` | 地面塌陷 |
| `4` | 泥石流 |
| `5` | 危岩 |
| `100` | 其他 |

### 2.3 事件等级

| 编码 | 名称 |
|---:|---|
| `1` | 小型 |
| `2` | 中型 |
| `3` | 大型 |
| `4` | 特大型 |

### 2.4 处置进度

| 编码 | 名称 |
|---:|---|
| `1` | 应急调查 |
| `2` | 会商研判 |
| `3` | 方案接入 |
| `4` | 响应执行 |
| `5` | 闭环归档 |

## 3. 左侧事件列表

### 3.1 基本信息

```http
GET /dizai/taskHandle/list
```

请求方式：Query String。

响应类型：`TableDataInfo<DzTaskHandleVo>`。

### 3.2 常用请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `pageNum` | number | 否 | 页码，建议从 `1` 开始 |
| `pageSize` | number | 否 | 每页条数 |
| `eventName` | string | 否 | 事件名称，模糊查询，后端自动去除首尾空格 |
| `reviewStatus` | number | 否 | 复盘状态，取值见复盘状态枚举 |
| `eventType` | number | 否 | 事件类型 |
| `eventLevel` | number | 否 | 事件等级 |
| `handleProcess` | number | 否 | 处置进度 |
| `province` | string | 否 | 省份，精确匹配 |
| `city` | string | 否 | 地市，精确匹配 |
| `county` | string | 否 | 区县，精确匹配 |
| `street` | string | 否 | 乡镇或街道，精确匹配 |
| `village` | string | 否 | 村或社区，精确匹配 |
| `detailedAddress` | string | 否 | 详细地址，模糊查询 |

复盘页面当前主要使用 `pageNum`、`pageSize`、`eventName` 和 `reviewStatus`。

请求示例：

```http
GET /dizai/taskHandle/list?pageNum=1&pageSize=10&eventName=边坡&reviewStatus=0
```

### 3.5 地图定位及弹窗

地图定位不需要新增接口：

1. 优先使用 `longitude`、`latitude`；
2. 两个字段任一为空时，不展示定位按钮或采用前端约定的不可定位状态；
3. `mapCoordinates` 是后端保留的原始 WKT，不建议前端再次解析；
4. 地图弹窗中的事件标题、类型、等级、地址、发生时间、威胁对象、处置概况、措施、
   图片数量和调查报告数量，直接使用当前列表行数据。

### 4.3 顶层字段

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `handleId` | long | 否 | 事件主键，前端按字符串处理 |
| `reviewStatus` | number | 否 | 复盘状态编码 |
| `reviewStatusName` | string | 否 | 复盘状态文案 |
| `eventOverview` | string | 是 | 后端根据已有事实生成的事件概况 |
| `tags` | string[] | 否 | 类型、等级、易发性和风险等级等非空标签 |
| `basicInfo` | object | 否 | 基本信息 |
| `impactInfo` | object | 否 | 影响情况 |
| `materialInfo` | object | 否 | 现场图片和调查报告 |
| `timeline` | object[] | 否 | 固定五步处置时间线 |
| `dataGaps` | string[] | 否 | 当前数据缺口名称 |

### 4.4 `basicInfo` 基本信息

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `disasterName` | string | 否 | 灾害名称；无现场名称时按地点或地址回退 |
| `disasterCode` | string | 否 | 当前使用事件主键的字符串形式 |
| `disasterType` | string | 是 | 灾害类型文案 |
| `cause` | string | 是 | 发生原因及补充说明 |
| `occurrenceTime` | datetime | 是 | 发生时间，依次回退到上报时间、创建时间 |
| `county` | string | 是 | 区县 |
| `detailedAddress` | string | 是 | 优先使用现场位置，其次使用主表详细地址 |
| `disasterLevel` | string | 是 | 优先使用现场规模等级，其次使用事件等级文案 |
| `stabilityStatus` | string | 是 | 现状稳定性 |
| `timeType` | string | 是 | 当前数据库无结构化字段，通常为 `null` |
| `hiddenDangerName` | string | 是 | 当前数据库无可靠关联字段，通常为 `null` |
| `susceptibilityLevel` | string | 是 | 斜坡单元易发性等级 |
| `riskLevel` | number | 是 | 动态风险等级编码，`0` 无风险、`1` 低、`2` 中、`3` 高、`4` 极高 |
| `riskLevelName` | string | 是 | 动态风险等级文案 |

### 4.5 `impactInfo` 影响情况

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `threatObject` | string | 是 | 威胁对象，现场记录为空时回退到影响范围 |
| `evacuatedHouseholds` | number | 是 | 实际撤离户数 |
| `evacuatedPeople` | number | 是 | 实际撤离人数 |
| `injuredPeople` | number | 是 | 受伤人数 |
| `missingPeople` | number | 是 | 失踪人数；当前数据库没有结构化字段 |
| `deadPeople` | number | 是 | 死亡人数 |
| `directLoss` | decimal | 是 | 直接经济损失，单位为万元 |

实际撤离户数和人数只从现场撤离执行说明中识别，例如“已组织 6 户 18 人临时避险”。
受威胁户数和受威胁人数不会被当作实际撤离数据。如果原始说明不包含可识别的“户/人”格式，
这两个字段返回 `null`，且 `dataGaps` 包含“实际撤离户数/人数”。

### 4.6 `materialInfo` 现场资料

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `photoCount` | number | 否 | 当前聚合出的图片总数 |
| `photos` | `AttachmentItem[]` | 否 | 图片附件，包括全貌、变形、受损和任务反馈图片 |
| `investigationReportCount` | number | 否 | 有效调查报告附件数量 |
| `investigationReports` | `AttachmentItem[]` | 否 | PDF、Word 等调查报告附件 |
| `attachments` | `AttachmentItem[]` | 否 | 图片、调查报告及其他附件的合并列表 |

`AttachmentItem`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `id` | long | 是 | 附件关联记录主键；旧现场图片可能为空，非空时按字符串处理 |
| `attachmentType` | number | 否 | `1` 图片、`2` 调查报告、`3` 补充资料 |
| `attachmentTypeName` | string | 否 | 附件类型名称 |
| `category` | string | 否 | 图片类别或 `INVESTIGATION_REPORT` 等业务分类 |
| `fileId` | string | 是 | 兼容字段，优先为 `ossId`，否则为 `sourceFileId` |
| `ossId` | long | 是 | 本系统 OSS 文件 ID；非空时按字符串处理 |
| `sourceFileId` | string | 是 | 第三方系统文件 ID |
| `externalUrl` | string | 是 | 第三方可访问地址 |
| `fileName` | string | 是 | 原始文件名 |
| `fileExtension` | string | 是 | 文件扩展名，如 `jpg`、`pdf`、`docx` |
| `mimeType` | string | 是 | MIME 类型 |
| `fileSize` | long | 是 | 文件字节数 |
| `description` | string | 是 | 附件说明 |
| `sourceSystem` | string | 是 | 来源系统 |
| `createdAt` | datetime | 是 | 附件产生或入库时间 |

前端预览顺序为：`externalUrl` 非空时直接使用；否则 `ossId` 非空时调用项目已有
OSS 预览/下载能力；只有 `sourceFileId` 时需由后续第三方文件服务解析。不要把
`sourceFileId` 传给本地 OSS 接口。`fileId` 仅用于兼容旧现场图片字段。

当前现场记录及任务反馈中的历史图片只保存了 OSS ID，因此可能出现 `fileId` 有值、
`ossId` 为空的情况。当前 Mock 图片的 `fileId` 均为本系统 OSS ID，前端可以在
`ossId` 为空时将纯数字 `fileId` 作为 OSS ID 使用。新附件记录应优先使用 `ossId`。

### 4.7 `timeline` 处置时间线

接口固定按以下顺序返回五个节点，前端不需要自行排序，也不应根据数组长度推断步骤：

| `code` | `name` | `available = true` 的条件 |
|---|---|---|
| `REPORT` | 事件上报 | 事件主记录存在；当前节点固定返回 |
| `DISPATCH` | 调查任务派发 | 存在关联的未删除任务 |
| `FEEDBACK` | 现场调查反馈 | 存在现场记录，或任务存在提交时间 |
| `REPORT_GENERATED` | 调查报告生成 | 存在最新有效调查报告 |
| `FOLLOW_UP_ARCHIVE` | 后续处置与归档 | 处置进度已闭环归档，或存在已关闭任务 |

每个节点字段：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `code` | string | 否 | 稳定的节点编码，前端逻辑判断应使用此字段 |
| `name` | string | 否 | 节点展示名称 |
| `available` | boolean | 否 | 是否存在支持该节点的实际数据 |
| `occurredAt` | datetime | 是 | 节点时间 |
| `operator` | string | 是 | 操作人、上报人或调查人 |
| `description` | string | 是 | 节点摘要 |
| `warning` | string | 是 | 时间冲突等核验提示 |
| `location` | string | 是 | 现场反馈地点 |
| `details` | string[] | 否 | 任务、报告或归档明细 |
| `photos` | `AttachmentItem[]` | 否 | 节点关联图片附件 |

当 `available = false` 时，节点仍然存在，但时间、操作人和描述可能为 `null`。
前端建议展示灰色未完成/资料缺失状态，不要隐藏节点，也不要自行补全时间和人员。

### 4.8 `dataGaps` 数据缺口

当前可能返回：

- `事件时间类型`
- `隐患点名称`
- `实际撤离户数/人数`
- `失踪人数`
- `处置任务派发与反馈`

`dataGaps` 表示数据库当前缺少可靠结构化事实，不等同于业务值为零。例如：

- `missingPeople = null`：没有可靠数据；
- `missingPeople = 0`：已明确无人失踪；
- `dataGaps` 包含“失踪人数”：UI 应展示“待补充”或“暂无可靠数据”，不能展示为 `0人`。

### 4.10 附件预览与下载

批量申请 10 分钟有效的私有文件访问地址：

```http
POST /dizai/oss/apply-url
Content-Type: application/json

{
  "ids": [
    "2101884573066485762",
    "2101884593551466497"
  ]
}
```

响应中的 URL 顺序与请求 `ids` 顺序一致：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    "http://minio-host/bucket/path/image.png?...",
    "http://minio-host/bucket/path/report.pdf?..."
  ]
}
```

单文件下载：

```http
POST /dizai/oss/down-url/{ossId}
```

该接口直接返回文件流，不是 `R<T>` JSON。前端下载时应按 `blob` 处理响应。

推荐处理逻辑：

```ts
function resolveOssId(item: ReviewAttachment): string | null {
  if (item.ossId) return item.ossId
  return item.fileId && /^\d+$/.test(item.fileId) ? item.fileId : null
}
```

图片、PDF 可以使用 `apply-url` 返回的临时地址预览；Word 文件建议调用下载接口，
或者交给前端已有的 Office 预览组件处理。临时地址过期后应重新申请，不要长期缓存。

## 5. 推荐页面调用流程

```text
进入复盘页面
→ 调用 GET /dizai/taskHandle/list
→ 使用 rows 渲染左侧列表和地图标记
→ 默认选中第一条可用事件
→ 使用选中行 id 调用 GET /dizai/taskHandle/reviewDetail/{id}
→ 使用 data 渲染右侧详情
→ 切换列表项时取消上一次未完成的详情请求，重新请求新 id
→ 筛选、翻页或刷新列表后，检查当前选中 id 是否仍存在
```

建议前端不要把右侧详情永久合并回列表行对象。列表用于轻量分页和地图展示，详情应按当前
选中的 `id` 独立缓存，避免翻页或筛选时产生字段残留。

## 6. 异常处理

### 6.1 通用成功响应

详情接口使用统一响应体：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

列表接口使用分页响应体：

```json
{
  "code": 200,
  "msg": "查询成功",
  "total": 0,
  "rows": []
}
```

### 6.2 前端处理建议

- `code !== 200`：展示后端 `msg`；
- 列表 `rows = []`：展示空状态，不调用详情接口；
- 详情事件不存在或当前用户没有数据权限：后端返回失败信息，前端清空右侧旧数据；
- 详情部分字段为 `null`：按字段缺失处理，不应把整个接口判定为失败；
- `available = false`：属于正常响应，不是接口异常；
- 快速切换事件时，应防止旧详情请求后返回并覆盖当前选中事件。

## 8. 当前接口边界

本文档中的两个接口只负责查询：

- 左侧列表接口不返回完整报告正文和完整处置时间线；
- 右侧详情接口把图片和调查报告统一作为附件元数据返回，不返回调查报告文件正文；
- 生成复盘报告、查询复盘报告正文、编辑、重新生成和人工确认将在算法接口协议确定后继续对接；
- 地图定位和地图弹窗无需新增接口；
- 本地附件通过 `ossId` 复用项目文件服务，第三方附件使用 `externalUrl` 或后续第三方文件服务。
