# 会议室前端与服务端对接

同一会议室业务的前端接口、媒体接入与转写协议在本文统一维护；业务规则见 [business](../../business/meeting/README.md)，未验证 SDK 原型见 [discovery](../../discovery/meeting/frontend-sdk-example.md)。

## 当前实现范围

| 项目 | 当前实现事实 |
| --- | --- |
| 协议/版本 | 前端与 Java HTTP/JSON；Java 到 Python HTTP/1.1；LiveKit 服务端 SDK 0.12.1 |
| 方向与入口 | 前端 → Java `/meeting/**`；前端 → LiveKit SDK；Java → Python；Python → Java 内部回调 |
| 认证边界 | 前端使用系统 `bwy-token`；LiveKit 使用后端签发的短期凭证；内部回调使用 `X-Transcriber-Key` |
| 调用方/影响面 | 会议列表、详情、入会、成员管理、文字记录页面及 Python 采集服务 |
| 实现与验证范围 | 已核对 HTTP/字段契约并归档模拟 ASR 链路证据；真实 ASR、正式登录及前端页面未完成验收 |

前端阅读顺序：接入流程 → 12 个接口 → 请求响应字段 → 文字与状态 → 邀请事件 → 错误处理。前端不调用内部回调或 Python 接口。

## 契约与映射

### 接入约定与调用流程

前端只调用 Java 的 `/meeting/**` 和 LiveKit 客户端 SDK，不调用 Python 或 `/internal/**`，不持有服务间密钥。系统登录请求头为 `bwy-token`，值使用登录返回的原始 Token，不添加 `Bearer`。

1. 会议列表：`GET /meeting/meetings?pageNum=1&pageSize=20`；创建选人：`GET /meeting/users?keyword=关键词&pageNum=1&pageSize=20`。
2. 创建：提交主题、说明和参会人 ID，使用返回的 `data.meeting.id` 打开详情；创建不等于加入媒体房间。
3. 入会：读取详情，再调用 `POST /meeting/meetings/{meetingId}/token`；用返回的 `url/token` 连接 LiveKit，按用户选择开启麦克风/摄像头。最终授权以领取凭证的结果为准。
4. 会中：成员与主持人身份取自 Java 详情；在线状态、音视频轨道、共享、设备开关由 LiveKit SDK 提供。主持人邀请/移除成功后刷新详情。
5. 文字记录：读取 `/transcripts` 与 `/transcription`；当前没有字幕推送，可在记录面板打开时按需轮询，关闭面板/卸载页面后取消请求和定时器。
6. 普通离开：包括主持人离开，都只执行 SDK 断开并清理设备、监听器；不调用 `/end`，不改变成员资格。再次进入重新领取凭证。
7. 结束：仅主持人调用 `POST .../end`；成功后清理本地媒体、刷新详情和文字。会议 `ENDED` 与文字 `COMPLETED` 是不同状态，`STOPPING` 时仍可能补入尾句。
8. 会后：有效成员可分页回看文字；只在主持人的已结束会议上显示删除入口，删除会一并移除文字历史。

这里描述前端应遵循的接入流程，不代表当前仓库已经实现或验收了前端页面。

### 接口矩阵

下列接口由 `MeetingController` 和 `IMeetingServiceImpl` 提供；路径不包含前端代理或网关额外前缀。

| 动作/事件 | 输入 | 输出 | 错误/状态映射 | 实现入口 |
| --- | --- | --- | --- | --- |
| POST `/meeting/meetings` | 创建对象 | 详情对象 | 有效登录；整批校验，创建请求无幂等键 | create / createMeeting |
| GET `/meeting/meetings` | `pageNum,pageSize` | 会议分页 | 当前用户有效成员资格对应的会议 | list / listMeetings |
| GET `/meeting/meetings/{meetingId}` | 路径会议 ID | 详情对象 | 仅 ACTIVE 成员，ENDED 会议仍可查看 | detail / getMeeting |
| PUT `/meeting/meetings/{meetingId}` | 路径 ID、更新对象 | 详情对象 | 仅主持人；ACTIVE/ENDED 均可改展示内容 | update / updateMeeting |
| DELETE `/meeting/meetings/{meetingId}` | 路径会议 ID | 空结果 | 仅主持人且 ENDED；物理删除，重复删除报不存在 | delete / deleteMeeting |
| POST `/meeting/meetings/{meetingId}/token` | 路径会议 ID，无 body | LiveKit 凭证 | 会议 ACTIVE 且成员 ACTIVE；账号必须有效 | token / issueToken |
| POST `/meeting/meetings/{meetingId}/participants` | `userIds` 非空数组 | 空结果 | 仅主持人且会议 ACTIVE；批次无效则整批失败 | addParticipants |
| DELETE `/meeting/meetings/{meetingId}/participants/{userId}` | 会议 ID、用户 ID | 空结果 | 仅主持人且会议 ACTIVE；禁止移除主持人 | removeParticipant |
| POST `/meeting/meetings/{meetingId}/end` | 路径会议 ID，无 body | 详情对象 | 仅主持人；已结束则直接返回详情 | end / endMeeting |
| GET `/meeting/users` | `keyword,pageNum,pageSize` | 用户分页 | 有效登录；排除已禁用、已删除账号 | users / listUsers |
| GET `/meeting/meetings/{meetingId}/transcripts` | `pageNum,pageSize` | 最终文字分页 | ACTIVE 成员可查，ENDED 会议仍可查，按发言开始时间及主键升序 | transcripts / listTranscripts |
| GET `/meeting/meetings/{meetingId}/transcription` | 会议 ID | 转写状态、错误、enabled/available | ACTIVE 成员可查；默认关闭，不影响旧凭证响应 | transcription / getTranscriptionStatus |

分页返回 `{code,msg,data,total}`，普通结果返回 `{code,msg,data}`，空结果的 `data` 可为 null 或缺省。分页数组字段为 `data`。成功以 `code === 200` 判断；业务异常可能包装在 HTTP 200 中，HTTP 非成功状态也须处理。不要依赖示例中的 `msg` 文案做分支。

分页显式传 `pageNum=1&pageSize=20`，页码从 1 开始；公共默认 pageSize 为最大整数。会议列表按创建时间、ID 降序，用户目录按用户 ID 升序；`keyword` 匹配账号名或昵称。当前会议列表没有标题/状态筛选参数。

2026-09-14 新增可选转写：启用后领取凭证自动触发 Python 采集，故障不阻断原会商；文字只从 Java 查询，不依赖 LiveKit 保存历史。转写片段字段与状态见下文“前端文字记录与状态”，服务间调用见“服务端转写对接”。当前真实 ASR 尚未实现，联调数据带 `mock=true`。

### 字段映射

| 对象字段 | 中文含义与约束 |
| --- | --- |
| 创建 `title` | 会议主题；必填非空白，最大100字符，保存时去首尾空白 |
| 创建 `description` | 会议说明；可不传/null，最大2000字符 |
| 创建 `participantIds` | 初始受邀系统用户 ID 数组；可省略或为空，主持人自动加入 |
| 更新 `title` | 同创建主题；PUT 必须提供完整主题 |
| 更新 `description` | 新说明；省略或传 null 都清空原说明，传空串保存空串 |
| 邀请 `userIds` | 待邀请 ID 数组；去重，整批验证有效后才写入；无效 ID 使整批失败 |
| `meeting.id/title/description` | 会议 ID、主题、说明 |
| `meeting.hostUserId/hostName` | 主持人 ID、创建时名称快照 |
| `meeting.status` | `ACTIVE` 进行中；`ENDED` 已结束，不存在重新开启接口 |
| `meeting.createdAt/endedAt` | 创建时间、结束时间；未结束的结束时间为空 |
| `meeting.transcriptionTaskId/transcriptionStatus/transcriptionError/transcriptionUpdatedAt` | 会议持久化的任务标识、状态、错误和更新时间；实时可用性以 `/transcription` 返回的 `enabled/available/status` 为准 |
| `participants[].id/meetingId/userId` | 成员记录 ID、所属会议 ID、系统用户 ID |
| `participants[].name` | 成员名称快照；重新邀请时刷新 |
| `participants[].role` | `HOST` 主持人；`PARTICIPANT` 普通参与者 |
| `participants[].status` | `ACTIVE` 有效邀请；`REMOVED` 已移除，不代表媒体在线/离线 |
| `participants[].invitedAt` | 最近邀请或恢复资格时间 |
| 用户 `userId/username/displayName` | 用户 ID、登录账号、显示名称（昵称优先）；不含手机号 |
| 凭证 `token/url/roomName/expiresAt` | 短期凭证、连接地址、房间名、凭证到期时间；`url` 与服务端 Admin API 共用 `dizai.livekit.url` |

详情包含 ACTIVE 和 REMOVED 成员，按邀请时间升序。对已 ACTIVE 用户重复邀请不会重复发通知；重新邀请 REMOVED 用户会恢复资格。当前无主持人转让、后台离开、rejoin、recall 或在线人数接口；前端展示和媒体交互见本文调用流程及 [SDK 原型](../../discovery/meeting/frontend-sdk-example.md)。

模型与请求定义见 [MeetingRecord](../../../../chongqing-geological-disaster-service/src/main/java/cn/edu/pku/whai/geological/disaster/service/meeting/domain/model/MeetingRecord.java)、[MeetingMemberRecord](../../../../chongqing-geological-disaster-service/src/main/java/cn/edu/pku/whai/geological/disaster/service/meeting/domain/model/MeetingMemberRecord.java)、[CreateMeetingRequest](../../../../chongqing-geological-disaster-service/src/main/java/cn/edu/pku/whai/geological/disaster/service/meeting/domain/req/CreateMeetingRequest.java)、[UpdateMeetingRequest](../../../../chongqing-geological-disaster-service/src/main/java/cn/edu/pku/whai/geological/disaster/service/meeting/domain/req/UpdateMeetingRequest.java)、[ParticipantIdsRequest](../../../../chongqing-geological-disaster-service/src/main/java/cn/edu/pku/whai/geological/disaster/service/meeting/domain/req/ParticipantIdsRequest.java)；响应组合见 [MeetingDetailVo](../../../../chongqing-geological-disaster-service/src/main/java/cn/edu/pku/whai/geological/disaster/service/meeting/domain/resp/MeetingDetailVo.java) 与 [LiveKitToken](../../../../chongqing-geological-disaster-service/src/main/java/cn/edu/pku/whai/geological/disaster/service/meeting/media/LiveKitToken.java)。

### 前端文字记录与状态

`GET /meeting/meetings/{meetingId}/transcripts?pageNum=1&pageSize=20` 返回 `{code,msg,data,total}`。空记录为 `data: []`、`total: 0`，不能据此认定转写正常，需结合状态接口。列表按 `startedAt,id` 升序；轮询刷新时按 `id` 去重，不反复追加同一条记录。

| 片段字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | string | 文字记录主键，可作列表稳定键 |
| `meetingId` | string | 所属会议 |
| `taskId/segmentId` | string | 采集任务/片段标识，后端用于幂等 |
| `userId/speakerName` | string | 发言人用户 ID、姓名快照 |
| `text` | string | 最终文字；以纯文本渲染，不作为 HTML |
| `startedAt/endedAt` | ISO-8601 string | 发言片段起止时间，不是回调接收时间 |
| `mock` | boolean | true 为模拟 ASR 结果，前端应明确标记“模拟转写” |
| `createdAt` | ISO-8601 string | 文字入库时间 |

以下 JSON 仅为字段示例，不是真实发言：

```json
{
  "code": 200, "msg": "查询成功", "total": 1,
  "data": [{
    "id": "20001", "meetingId": "10001", "taskId": "task-example",
    "segmentId": "segment-example", "userId": "102", "speakerName": "李四",
    "text": "[模拟转写] 示例文字", "startedAt": "2026-09-14T07:00:00Z",
    "endedAt": "2026-09-14T07:00:03Z", "mock": true,
    "createdAt": "2026-09-14T07:00:04Z"
  }]
}
```

`GET /meeting/meetings/{meetingId}/transcription` 返回普通 `R`：

```json
{
  "code": 200, "msg": "操作成功",
  "data": {
    "meetingId": "10001", "taskId": "task-example", "status": "STOPPING",
    "error": null, "updatedAt": "2026-09-14T07:01:00Z",
    "enabled": true, "available": true
  }
}
```

| 状态字段/值 | 含义与前端处理 |
| --- | --- |
| `enabled=false` | 功能关闭；显示“未启用转写”，不误报失败 |
| `enabled=true, available=false` | 无法确认 Worker 实时状态；显示服务不可用，不把缓存的 RUNNING 当作仍在记录 |
| `NOT_STARTED` | 尚未启动；首次领取凭证后由后端自动触发 |
| `STARTING` | 正在启动 |
| `RUNNING` | 正在采集转写 |
| `STOPPING` | 正在收尾，暂时继续刷新文字和状态 |
| `COMPLETED` | 任务已完成，刷新最终文字后停止自动轮询 |
| `FAILED` | 转写失败，显示 `error` 摘要；已存文字仍可查看，正常会商不受影响 |
| `taskId/error/updatedAt` | 当前任务标识、错误摘要、更新时间；兼容 null 或字段缺省 |

先判断 `enabled`，再判断 `available`，最后展示 `status`。当前没有面向前端的独立转写启停接口，也没有实时字幕事件；不要为重启转写循环调用领取凭证接口。

### 邀请事件

复用项目现有 SSE 连接与鉴权。自定义提醒封装的 `type` 是 `notify-custom`，内部 `data.type` 是 `meeting-invited`：

```json
{"type":"notify-custom","data":{"type":"meeting-invited","meetingId":"1966000000000000001"}}
```

收到提醒只刷新列表/提示邀请，用户点击后获取详情并判断是否仍可加入，不自动开麦或入会。SSE 为提交后的尽力提醒，离线/推送失败不影响会议邀请落库。

业务消息中心记录的 `type` 为 `meeting`，`bizData` 是 JSON 字符串，例如 `"{\"meetingId\":\"1966000000000000001\"}"`；使用 `JSON.parse` 并捕获解析异常后取 meetingId。旧消息可能对应已结束、已删除或已撤销资格会议，跳转失败应提示并回到列表。不要把该记录当作最新入会授权，也不要新增专用消息拉取接口。

映射依据：[SseService](../../../../chongqing-geological-disaster-service/src/main/java/cn/edu/pku/whai/geological/disaster/service/sse/service/SseService.java) 的 `notify-custom` 外层封装，以及 `IMeetingServiceImpl.notifyInvite` 的消息入库与提交后通知。

### 服务端转写对接

本节供后端/Python 维护，前端不直接调用。Java 使用 HTTP/1.1，Python 项目采用 Python 3.12、uv、FastAPI、httpx、LiveKit RTC SDK。所有内部调用携带 `X-Transcriber-Key`；Java 在会议事务提交后发起网络请求，回调使用短事务。

所有 ID 使用 JSON 字符串，时间使用含时区的 ISO-8601，统一转换为 UTC。

| 接口 | 输入 | 输出与语义 |
| --- | --- | --- |
| Python POST `/v1/meetings/{meetingId}/transcription/start` | `taskId,livekitUrl,roomName,token` | 立即返回任务快照，后台连接房间；同任务幂等，其他活动任务返回 409 |
| Python POST `/v1/meetings/{meetingId}/transcription/stop` | `taskId` | 发出收尾请求，最终状态通过回调或查询获取；不会停止不匹配的任务 |
| Python GET `/v1/meetings/{meetingId}/transcription` | 会议 ID | 任务快照；不存在或终态缓存已清理返回 404 |
| Java POST `/internal/meeting/transcription/segments` | `meetingId,taskId,segmentId,userId,text,startedAt,endedAt,mock` | 最终文字入库，按任务与片段唯一键去重 |
| Java POST `/internal/meeting/transcription/status` | `meetingId,taskId,status,error` | 更新当前任务状态，旧任务不能覆盖新任务 |

Python 快照字段为 `meetingId,taskId,status,error,updatedAt`，不包裹 Java `R`。Java 普通响应为 `{code,msg,data}`，分页为项目的 `TableDataInfo`；Python 回调必须同时检查 HTTP 成功和 `code == 200`。

`text` 最大 4000 字符，`taskId` 与 `segmentId` 不超过 128 字符。姓名由 Java 从会议成员记录取快照，不由 Worker 指定。正常每个账户一条麦克风音轨直接归属该账户；多人共用一个麦克风时不能自动映射为多个真实用户。

状态含义：`NOT_STARTED` 未启动、`STARTING` 启动中、`RUNNING` 运行中、`STOPPING` 收尾中、`COMPLETED` 已完成、`FAILED` 失败。数据库历史空状态在接口映射为 `NOT_STARTED`；关闭开关与任务状态分别表达。

## 可靠性与安全

### 认证和敏感字段

- 沿用项目现有登录流程。访问下述后端接口时携带系统登录 token，当前配置请求头名为 `bwy-token`，值使用登录结果原始 token；不要擅自添加 `Bearer`。
- API 地址沿用前端现有代理/baseURL，下表路径为服务端路由，不含网关前缀。
- `/token` 返回的是 LiveKit 短期凭证，只用于 `room.connect(data.url, data.token)`，不能替代系统登录 token。
- 前端不需要、也不应接收 LiveKit `apiSecret`。不要记录 token、完整凭证响应或将凭证写入业务路由、通知、持久缓存；媒体连接中的协议传递由 SDK 处理。
- 使用响应中的 `url`，不要硬编码地址或自行推导房间。后端不再按内外网、客户端 IP 或 profile 分流；部署侧须保证唯一 `dizai.livekit.url` 同时可供后端 Admin API 和客户端连接。HTTPS 页面应配置可访问的 WSS 地址，并验证证书、媒体端口与网络连通性。
- 所有 ID（`id`、`meetingId`、`hostUserId`、`userId`）按字符串保存、比较和发送，禁止 `Number(id)`。时间按 ISO-8601 瞬时时间解析后转换为用户时区显示，空结束时间应兼容 null/字段缺省。

### 幂等、并发和事务

- 创建无请求幂等键；网络超时后先查询列表核对，不自动重发创建。
- 会议管理和 Token 签发通过同一会议行锁串行；会议及成员持久化复用现有 MyBatis-Plus/事务。
- 重复邀请已有效成员不会重复通知；重新邀请 REMOVED 成员恢复原记录。ACTIVE 会议内重复移除已 REMOVED 成员直接返回；已结束会议的成员变更仍拒绝。
- 已结束会议重复结束直接返回详情。删除只允许 ENDED，按转写历史、成员、主体顺序删除；删除后再次调用返回“会议不存在”。
- PUT 只修改标题和说明；说明省略或 null 都会清空，不修改主持人、成员或状态。
- 踢人/关房先调用 LiveKit，成功后更新数据库；媒体失败抛错且不修改数据库。媒体已经成功但数据库提交失败时，可以重试；网关把媒体 404 视为幂等成功。

### 超时、恢复和兼容边界

- 会议管理请求无后台补偿或死信队列，调用方显式处理失败并决定重试；Python 转写回调另有有限退避重试。重试不表示外部副作用具有分布式事务保证。
- 邀请消息同事务落库，SSE 在提交后尽力发送；SSE 失败时从现有消息中心读取，不把未收到 SSE 当成未被邀请。
- 普通离开通过客户端 SDK 完成，不调用后台结束接口；媒体在线状态由 SDK 维护。前端未验证 SDK 代码见 [discovery 原型](../../discovery/meeting/frontend-sdk-example.md)。
- 移除或结束后禁止重新领取 Token；既有 Token 的有效期及重连行为遵循 LiveKit，不宣称后端实现了即时凭证撤销。
- 复用 `dizai.livekit` 配置。API 地址和部署版本由环境提供；当前文档没有承诺某个已上线地址已提供这些接口。

### 服务端可靠性与运行限制

- 首次领取用户 LiveKit 凭证时触发任务，用户凭证响应格式不变。Python HTTP 调用在会议事务提交后进行，回调状态写入使用短事务。
- Python 以单进程运行，只使用一个 Uvicorn worker。同一会议复用活动任务，重试同一文字不重复入库。
- Worker 使用 Java 签发的独立只订阅凭证；不使用用户身份、不持有 LiveKit 管理密钥、不发布音视频。
- 只处理真人用户的麦克风轨道；音频队列和文字回调队列有容量限制，识别过慢或回调重试耗尽按失败处理。
- 结束会议后刷新 ASR 尾段再完成任务；Java 默认接受 60 秒内的有效尾句。不会通过迟到状态回调延长窗口。
- Python 或 ASR 故障不影响原有入会、结束会商；状态查询显示错误。Python 重启不恢复音频，后续领取凭证可尝试重新启动。
- Python 终态任务仅短期保留；Java 已落库的历史文字和终态不依赖 Worker 内存缓存。
- 回调基地址固定取自 Python 环境配置，调用方不能逐请求指定回调地址。服务密钥、LiveKit 凭证、转写正文不进入应用请求日志。
- SQL 参数日志是独立边界：当前 test profile 的 P6Spy 默认开启，会记录 SQL 参数。处理真实转写前，应使用 JVM `-Dp6spy.config.exclude=meeting_transcript` 窄过滤该表，或明确设置 `SPRING_DATASOURCE_DYNAMIC_P6SPY=false`。本轮 fixture 关闭自身进程的 P6Spy，不修改现有 test 应用设定。
- 无磁盘音频备份和持久化回调队列：进程崩溃前尚未入库的数据不保证恢复，不能将 mock 验证描述为真实 ASR 识别验收。
