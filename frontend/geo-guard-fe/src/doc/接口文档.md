## 1. 风险概览

### 请求

```http
POST /dizai/riskAssessment/statChatBanner
Content-Type: application/json
```

彭水县页面固定传县名：

```json
{
  "county": "彭水县"
}
```

可选行政区字段为 `province`、`city`、`county`、`street`、`village`；可选试点字段为 `pilotArea1`、`pilotArea2`。普通用户的可见行政区由服务端权限覆盖，前端不要把 `adRegionIds` 当作授权参数传入。

### 新增响应字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `riskSlopeCount` | `number` | 行政区内最新风险评估快照涉及的斜坡单元数 |
| `riskZoneCount` | `number` | 关联风险区/崩塌条带数 |
| `coveredAreaKm2` | `number \| string` | 覆盖面积，单位 km²；当前项目 JSON 配置下零值可能序列化为字符串 |
| `affectedPopulationCount` | `number` | 关联人口数，按人员 ID 去重 |
| `affectedBuildingCount` | `number` | 关联房屋数，按建筑编码/房屋 ID 去重 |
| `coveredTownCount` | `number` | 覆盖乡镇数 |
| `townRiskRanking` | `array` | 按斜坡单元总数倒序的前 5 个乡镇 |

`townRiskRanking` 项字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `rank` | `number` | 从 1 开始的连续排名 |
| `townName` | `string` | 乡镇/街道名称 |
| `townCode` | `string \| null` | 乡镇/街道行政区划编码 |
| `noRiskCount` | `number` | 0：无风险 |
| `lowRiskCount` | `number` | 1：低风险 |
| `mediumRiskCount` | `number` | 2：中风险 |
| `highRiskCount` | `number` | 3：高风险 |
| `veryHighRiskCount` | `number` | 4：极高风险 |
| `totalCount` | `number` | 五个等级数量之和 |

排序统计全部风险等级 `0~4`，不是只统计高风险和极高风险。SQL 先按每个斜坡单元取最新评估，再按 `street/street_code` 聚合；请求带 `county=彭水县` 时，返回项均属于彭水县。

### 兼容保留字段

旧字段继续返回，前端新页面优先使用上面的新字段：

| 字段 | 说明 |
| --- | --- |
| `slopUnitCount` | 历史字段，名称存在拼写问题，保留兼容旧页面 |
| `highRiskCount`、`veryHighRiskCount` | 历史当日高/极高风险统计 |
| `keypointArea` | 历史重点区域 Top3，项结构为 `{name, code}` |
| `unHandleReportCount`、`unfinishedEventTotalCount`、`handlingTaskCount` | 原有报灾/处置统计 |
| `statPush` | 原有任务推送统计 |

空数据示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "riskSlopeCount": 0,
    "riskZoneCount": 0,
    "coveredAreaKm2": "0",
    "affectedPopulationCount": 0,
    "affectedBuildingCount": 0,
    "coveredTownCount": 0,
    "townRiskRanking": [],
    "slopUnitCount": 0,
    "highRiskCount": 0,
    "veryHighRiskCount": 0,
    "keypointArea": []
  }
}
```

## 2. 风险等级及今日变化

### 请求

```http
POST /dizai/riskAssessment/stat
Content-Type: application/json
```

建议与概览使用相同的行政区条件，并传 `offset=1` 表示今日：

```json
{
  "offset": 1,
  "county": "彭水县"
}
```

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `stat` | `array` | 始终返回动态风险等级 0、1、2、3、4 五项；缺失等级 `count=0` |
| `stat[].dynamicRiskLevel` | `number` | 风险等级：0 无、1 低、2 中、3 高、4 极高 |
| `stat[].count` | `number` | 当前统计窗口数量 |
| `diffRisk` | `object` | 上一统计窗口到当前窗口的数量变化；JSON 对象键为字符串 `"0"`~`"4"` |
| `statArea` | `object` | 现有行政区风险统计，按风险等级分组 |
| `statAttribution` | `object` | 现有高/极高风险归因统计 |
| `statDevice` | `array` | 设备统计；可选视图缺失时为空数组 |
| `statHazardPoint` | `array` | 隐患点统计 |

示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "stat": [
      {"dynamicRiskLevel": 0, "count": 0},
      {"dynamicRiskLevel": 1, "count": 0},
      {"dynamicRiskLevel": 2, "count": 0},
      {"dynamicRiskLevel": 3, "count": 0},
      {"dynamicRiskLevel": 4, "count": 0}
    ],
    "statArea": {},
    "statAttribution": {"3": {}, "4": {}},
    "diffRisk": {"0": 0, "1": 0, "2": 0, "3": 0, "4": 0},
    "statDevice": [],
    "statHazardPoint": []
  }
}
```

前端百分比可按 `count / stat 总数` 计算；总数为 0 时显示 `0%`。`diffRisk` 为数量差，不是百分比。

## 3. 推荐调用流程

1. 页面进入或切换县域时，并行调用 `statChatBanner` 和 `stat`。
2. 两个请求使用同一组行政区参数；彭水县页面固定带 `county=彭水县`。
3. 概览卡片使用 `riskSlopeCount` 等新字段；排序使用 `townRiskRanking`。
4. 风险等级条使用 `stat`，按 `dynamicRiskLevel` 建立固定 0~4 顺序，再展示 `diffRisk`。
5. `code` 非 200 或 HTTP 401/403 时按项目统一错误/登录失效流程处理；业务成功但数据为空是正常状态，不显示请求失败。

## 可靠性与安全

- 统计查询只读，不产生业务写入；服务端按用户行政区权限限制数据范围。
- 不要依赖前端传入 `adRegionIds` 获得权限；服务端会根据登录用户重新计算权限范围。
- 概览指标来自最新风险评估快照，避免同一斜坡历史评估重复计数。
- 人口、房屋、风险区或设备统计源为空/不可用时，对应字段返回 0 或空数组；前端应保留布局并展示空状态。
- 新增字段为响应追加字段，旧字段继续返回；前端应忽略未知字段以保持版本兼容。
